# PPT Design

Design is a way to make the argument visible. Begin with the page messages and evidence. Use the user's governing template when supplied; adapt the visual system only within the requested changes.

## Choose a visual language

Read [style-and-layout-routing.md](references/style-and-layout-routing.md). Resolve style in this order: explicit user direction or native template; authoritative brand system; appropriate examples for the audience and domain; a restrained readable starting point. Do not infer a dark palette from technology or gold from luxury.

Capture a compact design spec: canvas, grid/margins, title/body/data/source roles, available fonts/fallbacks, palette, image treatment, density, native/raster classification and example page mechanics. Cite official brand assets when using them. Do not impose a single page count, layout or white/black alternation.

## Make each page serve its message

- Use a chart for a measured comparison, trend or distribution; a table for exact multi-attribute lookup; a flow for causality/process; a diagram for relationships; a photo for a concrete subject or emotional opening.
- Choose graphics from the relationship in the data. Preserve scale, units, periods and categories. Use zero baselines for ordinary bar comparisons; label any justified nonzero axis. Avoid 3D charts and fabricated values.
- Keep one dominant message per page while allowing the evidence density appropriate to the audience. A financial appendix can be dense; a classroom explanation needs progressive examples. Neither must look like a photographic cover.
- Adjust content hierarchy and page mechanics before shrinking text. Keep essential caveats visible when they qualify the headline; use speaker notes for supporting detail, not to hide a material contradiction.
- Use a consistent font-role system. Confirm glyph coverage for CJK and math, credible numeric spacing, and readable strokes at projection size. Record any substitution that changes the accepted design.
- Review the sequence. Vary scale/crop/layout for a reason; do not repeat the same card wall, split page or photograph by default.

## Image-led work

When the user wants image-led design, follow the available image tool's skill. Give each prompt a specific subject, composition, lighting, quiet copy area, reference, exact copy when needed and exclusions. Inspect generated assets at full size; do not treat typography within a bitmap as native editability.

Use authentic assets for real people, products, sites and logos. Maintain a simple ledger of subject, source/provenance, permitted use, crop and pages. Check semantic repetition, including repeated crops of the same image. Generated art must not be presented as a real campaign or product.

If noir is selected, load [Noir PPT Studio](../noir-ppt-studio/SKILL.md). The governing principle remains specific photography and typography, not decoration.

## Handoff

Give production exact display copy/data, element roles, geometry, image crops and typography decisions. Keep charts, tables, labels, values and simple geometry native. Inspect the rendered PPTX before claiming the design survived export. Use [ppt-quality](../ppt-quality/SKILL.md) for final review.
