# Presentation Storyline

Translate a supported analysis into a story the intended audience can follow and act on. Keep evidence attached to its claim. Choose slide count and visual mechanism from the job; avoid a fixed-length deck.

## Build the arc

1. State the one takeaway the audience should remember and the decision/action/understanding sought.
2. Group evidence into the few themes that directly support, qualify or challenge that takeaway. Keep contradictions visible.
3. Choose an appropriate progression: situation→tension→choice→proof→action; question→method→finding→implication; performance→drivers→outlook→actions; options→criteria→tradeoffs→recommendation; or a timeline/process when sequence itself is the point.
4. Assign each page one job and one lead conclusion. Use sentence titles that state a supported implication rather than only a topic. Retain evidence IDs in the page map and notes/ledger.
5. Add necessary definitions, baseline, method, comparator and counterargument before the claim that relies on them. Put secondary detail in an appendix; never bury a key caveat.
6. Select a visual mechanism that makes the relationship legible: photo, number, comparison, distribution, trend, driver tree, process, timeline, map or synthesis. Vary layouts where the argument changes; consistency need not mean one repeated grid.
7. Read only the slide titles in order. Correct any abrupt jump, unsupported causal step or repeated conclusion. Check that the ending resolves the opening question and names the next action or remaining uncertainty.

Use [storyline-method.md](references/storyline-method.md) for practical arcs and a slide map. Feed the accepted map to `ppt-studio` for visual direction and editable production. An explicit user template controls appearance; Noir is an optional style, never implied by analysis.

## Practical rules

- Use the minimum slide count that completes the case. Respect a requested count when feasible; disclose when evidence cannot support a page without filler.
- Keep each page to one main claim and a focused set of support. Dense evidence may require a chart/table appendix or companion workbook.
- Use parallel comparisons with equal time periods, categories and measures. State units and baselines on the page or directly next to the data.
- Give charts descriptive titles and show source, interval and method. Never choose a chart before understanding the data structure.
- Distinguish aspiration, recommendation and achieved outcome in headlines and visual status.
- Separate the spoken explanation from the slide: the canvas carries the conclusion and proof; notes add qualification, sources and presenter context.
- Do not force a problem-solution-investment-ask sequence onto academic, policy, teaching or periodic-status decks unless it fits the purpose.

This skill works alone. It can use an existing page list as a starting point, but must identify gaps, duplication and unsupported claims before calling it final.
